# Formato del reporte

Este mismo texto va en la respuesta a Nick y en `proyectos/skills/monitor/AAAA-MM-DD.md`.

```
## Revisión de skills — AAAA-MM-DD
Semáforo: 🟢/🟡/🔴 — <una frase: cómo está el conjunto>
Periodo revisado: <desde> a <hasta> · <n> sesiones vistas (<dónde: Project X o fuera de Projects>) · <n> bitácoras

### Las 4 respuestas
- **Sobra:** <skill — razón> o "ninguna"
- **Actualizar:** <skill — qué> (una línea cada una)
- **Mejorar:** <skill — qué> (máx. 3)
- **Crear:** <nombre propuesto — para qué> (máx. 3)

### Estado de cada skill
| Skill | Veredicto | Por qué (una línea) | Evidencia |
|---|---|---|---|

### Propuestas
#### 1. <Crear|Mejorar|Fusionar|Retirar> <skill>
- **Qué:** …
- **Por qué:** … (lo que se repite o falló)
- **Evidencia:** <link de la sesión o entrada de bitácora, fecha> (una o más)
- **Ahorro:** <cuántas veces / qué evita>
- **Brief** (solo para crear): nombre, disparadores, salida, límites, relación con otras, caso de prueba.

### También vi
- <cosas menores en una línea>

### Lo que no pude revisar
- <sesiones fuera de alcance, skills de Claude (no visibles desde Perplexity), repo no disponible, etc.>
```

Reglas:
- Las 4 respuestas van primero y deben entenderse sin leer el resto.
- "Evidencia" nunca va vacía en una propuesta.
- Sin párrafos largos. Si algo necesita más de 3 líneas, va como propuesta.
